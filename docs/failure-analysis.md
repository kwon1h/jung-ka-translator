# GitHub 배포형 게임 OCR 번역 앱 실패 원인 분석

게임 OCR 번역기는 아이디어는 강하지만 장기적으로 성공하기 어렵다. 실패 원인은 번역 품질 하나가 아니라 설치, 보안, 비용, 게임별 차이, 유지보수 흐름이 동시에 무너지는 데 있다.

## 1. 설치와 실행 조건이 복잡하다

문제:
- Windows OCR 언어팩, 창모드 전환, 관리자 권한, 그래픽 캡처 제한 등 사전 조건이 많다.
- 사용자는 OCR이 왜 안 되는지 알기 어렵다.

대응:
- README 첫 부분에 실행 전 조건을 짧고 명확하게 둔다.
- 앱 상태 메시지는 `창 종료`, `최소화`, `OCR 언어팩 없음`, `번역 API 실패`를 구분한다.
- 독점 전체 화면은 지원하지 않는다고 명확히 말한다.

## 2. OCR 품질이 게임마다 크게 흔들린다

문제:
- 게임 글꼴, 그림자, 배경 투명도, 해상도, 채팅창 애니메이션이 OCR 정확도를 크게 낮춘다.
- OCR 오인식이 번역 API로 넘어가면 이상한 번역이 누적된다.

대응:
- 채팅 영역만 좁게 캡처한다.
- 게임별 사전과 빠른 답장 문구를 적극적으로 사용한다.
- OCR 품질 필터와 수동 OCR 테스트 도구를 유지한다.
- 로그에 OCR 원문과 필터 판단을 남긴다.

## 3. API 비용과 토큰 사용량이 통제되지 않는다

문제:
- 같은 채팅을 매 프레임 번역하면 비용과 지연이 폭증한다.
- UI 고정어, 이미 번역한 문장, 깨진 OCR 결과까지 API로 보내면 사용자가 신뢰하지 못한다.

대응:
- 정확히 사전에 있는 문장은 API로 보내지 않는다.
- 동일 문장과 유사 채팅은 캐시로 막는다.
- 사전 치환 후 원문 언어가 남지 않으면 API 호출을 생략한다.
- 번역 실패 시 재시도 폭주를 만들지 않는다.

## 4. 보안 신뢰를 얻지 못한다

문제:
- 게임 유저는 계정 보안과 API 키 유출을 민감하게 본다.
- 오픈소스라도 키 저장, 로그, 네트워크 요청이 불투명하면 설치를 꺼린다.

대응:
- API 키는 Windows DPAPI로 현재 사용자 범위에 암호화 저장한다.
- 로그에는 키, 토큰, 인증 헤더를 절대 남기지 않는다.
- 네트워크 호출 대상과 저장 파일 위치를 문서화한다.
- 배포 zip에 사용자 설정이나 개발자 키를 포함하지 않는다.

## 5. 게임별 최적화 없이 범용 번역기처럼 만든다

문제:
- 범용 OCR 번역기는 게임 채팅의 짧은 문장, 빠른 답장, 고정 UI 용어를 제대로 처리하지 못한다.
- 게임마다 자주 쓰는 표현이 다르기 때문에 일반 번역 품질만으로는 부족하다.

대응:
- PopKart 기준 기본 사전을 계속 확장한다.
- 사전 항목은 UI 고정어, 채팅 빠른 답장, 트랙/모드명, 아이템/차량 용어로 분류한다.
- 사용자가 쉽게 사전을 추가/삭제할 수 있게 한다.
- 게임 패치 후 사전 업데이트를 릴리스 노트에 기록한다.

## 6. UI와 오버레이가 게임 조작을 방해한다

문제:
- 오버레이가 클릭을 막거나 캡처에 다시 잡히면 게임 플레이를 방해한다.
- 번역 결과가 원문 위에 겹쳐 읽기 어려워질 수 있다.

대응:
- 오버레이는 click-through를 기본으로 한다.
- 캡처 직전 오버레이를 숨겨 자기 캡처를 줄인다.
- 투명도, 글꼴 크기, 테두리 색, 테두리 두께를 설정 가능하게 한다.
- 27인치 FHD 기본값은 검은 반투명 배경, 흰 글씨, 검은 외곽선, 22pt 이상으로 둔다.
- 별도 결과 창 모드를 대안으로 유지한다.

## 7. 유지보수 기준 없이 기능만 늘린다

문제:
- 번역 엔진, OCR 엔진, 캡처 방식, UI 모드를 한 코드 경로에 섞으면 버그가 늘어난다.
- 기능을 추가할수록 어떤 실패가 재발했는지 추적하기 어렵다.

대응:
- `IWindowSource`, `ICaptureService`, `IOcrEngine`, `ITranslationService`, `ITranslationSession` 경계를 유지한다.
- 새 기능은 `guideline.md` 체크리스트를 통과해야 한다.
- 실패 사례는 가이드라인에 추가한다.
- 디버깅 도구를 기능과 함께 유지한다.

## 8. 로그가 부족해서 문제를 재현하지 못한다

문제:
- 사용자가 “번역이 안 된다”고 말해도 OCR 실패인지, API 실패인지, 필터 오탐인지 알 수 없다.

대응:
- OCR 원문, 파싱 결과 수, 필터 규칙, 필터 이유, 유사도 점수를 남긴다.
- 앱 안의 진단 로그 탭에서 최근 판단을 확인할 수 있게 한다.
- 로그 위치를 README에 명시한다.
- 민감정보는 남기지 않는다.

## 이 프로젝트의 성공 기준

- 사용자가 3분 안에 창 선택, 영역 선택, 번역 시작까지 갈 수 있다.
- 같은 채팅은 반복 번역되지 않는다.
- 사전에 있는 고정 문구는 API 비용 없이 즉시 표시된다.
- 오류가 발생해도 앱이 꺼지지 않고 로그로 원인을 확인할 수 있다.
- 보안 정책이 README와 코드에서 일관된다.
- 게임 패치와 사용자 피드백에 따라 사전과 필터가 계속 업데이트된다.
